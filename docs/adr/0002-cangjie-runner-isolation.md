# ADR 0002：仓颉执行器隔离边界

- 状态：接受
- 日期：2026-10-01

## 背景

学生提交的仓颉源码是不可信输入。执行器需要提供真实编译与运行结果，同时不能让源码借助文件路径、命令参数、进程、网络或宿主文件系统突破任务边界。

设计基线指定仓颉 1.0.5 cjnative。实现环境在 2026-10-01 实测为仓颉 1.2.0；对应 Linux x64 SDK 1.2.0 已由仓颉官网下载并通过官方 SHA256 `8c5fd944cd9cc51ee63d4a240e3ecc4f540345dae1468e8b47c927ecf2ba998f` 校验。该版本差异可能影响编译诊断格式、语言行为和 ABI，不能视为已证明兼容 1.0.5。

## 决策

执行器保持 ADR 0001 已批准的独立容器边界：

- 容器使用非 root 用户 `10001:10001`，删除全部 Linux capabilities，并启用 `no-new-privileges`；
- 容器无网络，根文件系统只读；每个任务只在 `/work` 下的新临时目录读写，结束后删除；
- `/work` 是归属 UID/GID 10001、限制为 64 MiB 的临时文件系统。它保留 `nosuid,nodev`，但为运行刚编译的受控产物显式启用 `exec`；容器设置 512 MiB 内存、64 PID、1 CPU，并由请求设置最长 30 秒的进程超时；
- 请求命令只接受 `cjc` 加已提交的相对 `.cj` 文件路径。调用者不能传入编译器选项、输出路径、shell、命令解释器或连接符；执行器以参数数组调用固定的 `cjc` 选项；
- 编译成功后只运行执行器生成的固定名称产物；超时时终止整个进程组；stdout 与 stderr 分别限制为 64 KiB；
- 源文件写入前再次拒绝绝对路径、父目录、Windows 盘符和符号链接路径。路径校验不只依赖 API 层；
- 编译器使用 JSON 诊断格式，随后规范化为不依赖 cjc 字段大小写和版本布局的稳定对象，供 Task 5 使用。

Compose 合并建议仅记录在 `runner/compose.fragment.yaml`，共享 `infra/compose/docker-compose.yml` 由协调 Agent 串行处理。

## 影响

- 运行时无网络，学生程序不能下载依赖或连接外部服务；需要额外包的课程任务必须预先纳入受审镜像。
- 只读根文件系统与临时工作区要求编译器缓存和产物都位于任务目录。
- PID、内存或 CPU 限制触发时，进程可能只返回平台相关信号或退出码；执行器统一标记已知的资源限制退出状态，容器级 OOM 仍需由上层结合容器状态审计。
- 1.2.0 是 STS，而设计基线 1.0.5 是 LTS。上线或评测冻结前必须由协调 Agent 决定回退到 1.0.5，或另行批准并验证 1.2.0 基线；本 ADR 不静默改变产品设计中的版本事实。
