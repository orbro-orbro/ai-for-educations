# ADR 0004：学习记忆、授权与可验证删除

- 状态：接受（用户于 2026-10-05 确认）
- 日期：2026-10-05
- 关联：ADR 0001、Task 2 身份与课程权限、Task 6 诊断与理解验证、Wave 2C Task 7

## 背景

Task 6 已持久化带 `course_id`、`owner_user_id` 的证据约束诊断和 `ExplanationCheck`，并只在诊断无需教师复核、诊断与解释置信度达标、解释体现理解且概念均来自当前课程已审核证据时设置 `memory_proposal_eligible=true`。Task 6 明确不存储长期记忆。

Task 7 需要把这一资格信号转换成学生可审阅的记忆提议，并提供接受、拒绝、纠正、过期、检索、授权、撤销和删除能力。教师默认不能读取学生私人对话或完整学习记忆；未知资源与无权资源继续使用统一的 `RESOURCE_NOT_AVAILABLE` 拒绝策略。删除可能跨越权威关系数据、派生检索索引和缓存，必须在外部清理失败时仍立即停止检索。

本 ADR 只决定 Task 7 的领域、权限和删除语义。它不改变角色、课程、主框架、数据库或不可信代码执行边界。

## 决策

### 1. `MemoryProposal` 与 `LearningMemory` 的边界

`MemoryProposal` 是待学生决定的建议，不是长期记忆，也不能进入任何学习上下文检索。它包含所有者、课程、来源诊断与理解验证、建议正文、概念、置信度、有效期、版本关系和状态。

`LearningMemory` 是学生明确接受后产生的课程内长期学习状态。它有独立 ID，并保留对被接受提议和来源诊断的引用。只有状态为 `active`、未到期、所有者与课程匹配且当前策略再次允许的版本才能参与检索。

提议正文与长期记忆正文均属于私人内容。公开 DTO 不直接暴露数据库行；教师接口永不返回 `LearningMemory` 正文。

### 2. Task 6 结果如何成为提议候选

提议服务只能消费服务端读取的 Task 6 记录，并同时验证：

1. `ExplanationCheck.memory_proposal_eligible=true`；
2. 对应 `Diagnosis.requires_teacher_review=false`；
3. 诊断置信度仍达到当前课程阈值；
4. 诊断、理解验证、提交的所有者和课程完全一致；
5. 当前学生仍有该课程访问权；
6. 同一 `ExplanationCheck` 尚未产生提议。

其中任何一项不成立都不能产生可接受提议。`memory_proposal_eligible=false` 是硬拒绝，不允许由请求参数、教师操作或模型输出覆盖。提议内容在 Task 7 中由确定性、经过验证的诊断字段构造；不调用真实或付费模型。

### 3. 只有所属学生能够激活长期记忆

模型、模型回调、教师和后台任务都不能创建或激活 `LearningMemory`。它们至多请求生成 `MemoryProposal`。唯一激活入口是已认证的提议所属学生调用接受操作，且服务端重新验证提议所有者、课程成员关系、状态和到期时间。

客户端不能提交 `owner_user_id`、`course_id`、激活状态、来源诊断、置信度或版本号等服务端控制字段。它只能提交接受、拒绝、纠正文等明确意图。

### 4. 生命周期状态机

`MemoryProposal` 状态为：

- `pending`：可由所属学生接受、拒绝或纠正；
- `accepted`：已原子地产生一个 `LearningMemory`，终态；
- `rejected`：学生拒绝，终态；
- `superseded`：学生纠正后由新提议版本替代，终态；
- `expired`：超过 `expires_at`，终态。

允许的转换只有：`pending -> accepted | rejected | superseded | expired`。纠正 `pending` 提议时，原提议变为 `superseded`，同时创建一个内容已纠正的新 `pending` 提议。读取或操作提议时若服务端时间已超过 `expires_at`，必须先把它视为并持久化为 `expired`；过期提议不能接受。

`LearningMemory` 状态为：

- `active`：当前可检索版本；
- `superseded`：已被学生纠正产生的新版本替代，不可检索；
- `expired`：超过 `expires_at`，不可检索；
- `deletion_pending`：已写入不可逆删除 tombstone，等待派生存储清理，不可检索；
- `deleted`：派生存储清理和反向检索验证完成，终态且不可检索。

允许的转换只有：`active -> superseded | expired | deletion_pending`、`superseded | expired -> deletion_pending`、`deletion_pending -> deleted`。`deleted` 没有出边。删除针对整个逻辑记忆版本链；任一版本发起删除时，该链全部立即进入不可见删除状态。

### 5. 纠正采用不可变新版本

提议和长期记忆都不原地覆盖私人正文。纠正会创建带 `root_id`、`previous_version_id` 和递增 `version` 的新记录，并把旧记录标记为 `superseded`。长期记忆纠正在一个权威存储原子操作中完成：先验证旧版本仍为当前 `active`，再创建新 `active` 版本并废止旧版本，因此任一时刻最多有一个可检索版本。

审计只记录纠正事件、旧/新资源 ID、版本号、操作者、课程、结果和时间，不记录修改前后正文，也不保存正文摘要或内容哈希。

### 6. 所有者与课程双重隔离

授权顺序固定为：

1. 认证并从服务端用户仓库重新确认角色与有效状态；
2. 从路径资源解析权威 `owner_user_id` 和 `course_id`，不采信客户端字段；
3. 确认当前学生是所有者；
4. 确认该学生当前仍是该课程成员；
5. 确认资源状态、到期和用途允许本次操作；
6. 才执行读取、状态转换或检索。

所有条件都采用 AND 关系。任何所有者、课程、角色、成员关系或资源关联不一致都统一返回 `RESOURCE_NOT_AVAILABLE`，不暴露资源是否存在。

### 7. 检索前过滤与结果返回前复核

关系数据是授权事实源，检索索引不是。语义检索采用以下固定顺序：

1. 先从权威仓库查询精确匹配 `owner_user_id + course_id + active + 未过期 + 用途` 的候选 ID；
2. 只把候选 ID 白名单及同样的所有者/课程元数据过滤条件交给检索索引；
3. 将索引返回 ID 与候选白名单取交集，忽略未知、重复或越界结果；
4. 重新从权威仓库加载每条结果，并再次执行所有者、课程、状态、到期、用途和当前成员关系检查；
5. 仅返回复核仍通过的 DTO。

索引返回空、陈旧或恶意结果都不能扩大权限。`deletion_pending`、`deleted`、`expired`、`superseded` 以及待确认提议在第一步即被排除，在第四步再次被排除。

### 8. `ShareGrant` 的最小授权范围

`ShareGrant` 只允许学生把一个明确的 `diagnosis_summary` 授权给管理同一课程的一个明确教师；它不授权 `LearningMemory` 正文、私人对话、其他诊断、其他记忆或整个课程历史。授权记录包含 `grant_id`、学生所有者、课程、资源类型、资源 ID、教师受让人、用途、创建时间、可选到期时间和状态。

创建授权时必须同时验证学生拥有该诊断、诊断属于当前课程、受让人是当前课程的拥有者或显式授权教师。访问时必须再次验证授权仍为 `active`、未到期、未撤销，受让教师仍管理该课程，且资源仍属于相同学生和课程。

状态为 `active -> revoked | expired`，`revoked` 和 `expired` 为终态。撤销从权威事务提交后立即生效；索引或缓存故障不能恢复访问。相同幂等键的重复创建返回同一授权，相同授权的重复撤销返回当前终态。

### 9. 教师默认拒绝私人记忆

教师无论是否拥有课程，都默认不能列出或读取学生的 `MemoryProposal` 或 `LearningMemory`，也不能代替学生接受、拒绝、纠正或删除。`ShareGrant` 仅开放其指定的诊断摘要读取，不把教师加入私人记忆读取者集合。普通课程授权和正式作业可见性均不能推导出记忆权限。

### 10. tombstone、`deletion_pending`、重试与完成

删除分成权威事务和可重试清理：

1. 在一个原子操作中验证学生所有权与课程，创建或复用唯一删除请求，把整个版本链标为 `deletion_pending`，清空关系记录中的私人正文，撤销与目标资源关联的有效授权，并写入不含正文的审计事件和 tombstone；
2. 事务提交后，该版本链立即从所有候选查询、缓存读取和上下文组装中排除；
3. 以保留的非敏感 opaque 索引文档 ID 清理检索索引、派生缓存和未完成模型任务引用；
4. 清理全部成功后，用相同所有者、课程和逻辑记忆条件执行反向检索验证；验证无结果后标记 `deleted` 并完成删除凭证；
5. 任一派生清理或验证失败时保持 `deletion_pending`，保存脱敏失败码和重试元数据，由显式重试入口再次执行第 3、4 步。

Task 7 不引入消息队列。补偿器是可直接调用的领域服务，测试使用确定性内存索引失败替身；生产调度由后续 Gate 或既有进程机制装配。

### 11. 索引删除失败仍立即停止检索

检索索引仅接收权威候选 ID 白名单。删除事务一旦把版本链置为 `deletion_pending`，这些 ID 就不再进入白名单；即使索引物理副本尚未删除，它也无法通过检索前过滤。若索引错误地返回陈旧 ID，结果返回前的权威状态复核仍会丢弃它。

因此“逻辑不可见”由关系状态保证，不依赖索引删除成功；“物理清理完成”由补偿重试和反向检索验证保证。二者分别记录，不能把 `deletion_pending` 描述为物理删除完成。

### 12. 删除凭证的允许与禁止字段

删除凭证只允许包含：`deletion_id`、逻辑 `memory_id`、`owner_user_id`、`course_id`、状态、请求时间、完成时间、重试次数、各派生存储的布尔清理结果、反向检索验证结果、脱敏错误码和 `request_id`。

删除凭证禁止包含：原始或纠正后的记忆正文、提议正文、私人对话、学生代码、解释原文、模型提示或响应、向量或 embedding、可还原正文的摘要/哈希、访问令牌、API Key、内部索引键、异常堆栈和供应商请求 ID。

### 13. 审计内容与最小化

敏感读取、提议决定、纠正、授权、撤销、删除、重试和删除验证均写审计事件。允许字段为：审计事件 ID、事件类型、操作者 ID 与角色、目标类型与 ID、所有者 ID、课程 ID、授权或删除 ID、结果、稳定原因码、请求 ID 和 UTC 时间。拒绝事件可记录统一原因码，但不能记录能帮助枚举资源的内部细节。

审计禁止记录任何私人正文、对话、代码、解释原文、提示词、模型输出、向量、令牌、密钥或内部堆栈。关系状态变更与对应审计在同一仓库原子操作中完成；敏感读取若不能可靠写审计则失败关闭，不返回正文。

### 14. 幂等与并发

- 提议生成以 `explanation_check_id` 为唯一来源键；重复调用返回同一提议。
- 接受、拒绝、纠正、授权和删除都要求服务端幂等键；同一资源与幂等键重复调用返回第一次结果。
- 同一提议的并发接受使用仓库级 claim/锁，并由后续 SQL 唯一约束保证最多一个 `LearningMemory` 引用该提议；失败竞争者重新读取并返回已提交结果。
- 已接受提议再次接受返回原记忆；已拒绝、过期或被纠正提议的接受是安全冲突，不创建记忆。
- 同一拒绝重复执行返回同一终态；接受后再拒绝或拒绝后再接受是冲突。
- 重复删除返回同一删除凭证；`deletion_pending` 的重复删除不重建任务，`deleted` 的重复删除不恢复任何数据。
- 删除重试按 `deletion_id` 串行化；已成功的清理步骤不重复产生副作用，`deleted` 上的重试返回完成状态。

只有在认证和资源归属检查通过后，API 才可返回状态冲突；未知或越权资源始终使用统一 404，避免 IDOR 信息泄露。

### 15. 关系数据与可替换检索索引的边界

关系仓库保存身份、课程成员关系、提议和记忆状态、版本链、授权、删除 tombstone/凭证、审计以及 opaque 索引文档 ID，是唯一权威事实源。索引只保存语义检索所需的派生文档与向量，不保存授权真相，也不能决定可见性或状态转换。

领域服务依赖最小 `RetrievalIndex` 端口：按候选 ID 与元数据过滤检索、删除指定文档、按同一过滤条件验证不存在。Task 7 使用确定性内存实现和失败替身；不引入外部向量数据库。索引可以重建或替换，而不改变领域策略。

### 16. Task 7 分支与 Task 7 Gate 的职责

本分支负责：领域模型与状态机、内存 Repository、授权策略、检索索引端口及确定性实现、删除补偿服务、最小审计服务、未挂载的 API router、Task 7 OpenAPI 片段，以及生命周期/隔离/授权/删除测试。

本分支不直接修改共享 `contracts/openapi.yaml`、迁移链、`backend/app/main.py`、Compose、环境变量示例或根级配置，也不实现前端、教师分析或安全评测。

后续 Task 7 Gate 负责：

1. 合并共享 OpenAPI；
2. 创建唯一的 `0005_memories_audit.py`；
3. 实现 SQL Repository、唯一约束和事务装配；
4. 在应用组合根挂载路由；
5. 验证 PostgreSQL 约束和迁移升级/降级往返；
6. 验证进程重启后的删除补偿恢复；
7. 冻结 Wave 3 教师分析所消费的去标识化契约。

## API 与错误语义

Task 7 片段将定义学生本人提议列表、接受/拒绝/纠正、课程内有效记忆列表、记忆纠正/删除、授权创建/查看/撤销、删除状态和显式补偿重试能力。所有端点使用 Bearer 认证、严格请求模型、统一错误信封和 request ID。

缺少或无效凭证返回统一认证错误；未知、外部所有者、跨课程或无权资源返回统一 `RESOURCE_NOT_AVAILABLE`；已授权后发现非法状态转换返回稳定冲突错误；输入结构错误返回统一校验错误；权威存储失败返回脱敏的不可用错误。任何错误响应都不包含私人正文、令牌、内部堆栈或索引细节。

## 被拒绝的方案

### 模型或回调直接写长期记忆

拒绝。它绕过学生明确同意，也让模型输出成为授权事实。

### 原地覆盖纠正内容

拒绝。它破坏版本追踪和可审计性，使并发纠正难以判定胜者。

### 先查全局向量索引再做权限过滤

拒绝。索引可能泄露跨学生或跨课程候选，也会把授权正确性绑定到派生系统。

### 等索引删除成功后才隐藏记忆

拒绝。索引故障会延长私人内容可见窗口，不满足删除开始即停止检索。

### 在 Task 7 引入外部向量库或消息队列

拒绝。当前需求可由端口、内存实现和显式补偿重试验证；新增基础设施会扩大范围且不能替代权威权限判断。

## 影响

- 学生对长期记忆拥有最终决定权，并能纠正、拒绝和删除。
- 教师课程管理权与私人记忆读取权严格分离；显式授权也只覆盖一个诊断摘要。
- 删除完成前可能存在不可访问的派生物理副本，因此 API 必须准确区分 `deletion_pending` 与 `deleted`。
- 不可变版本和 tombstone 会保留最小关系元数据；私人正文在删除权威事务中被清空，审计和凭证不能用于还原。
- Gate 必须用数据库约束兑现并发唯一性和事务原子性；本分支的内存锁只验证领域行为，不代表已验证真实 PostgreSQL。
