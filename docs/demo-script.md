# 比赛演示脚本：真实链路、合成数据

所有账号与数据均为合成；模型回答为确定性 Mock，编译反馈来自仓颉 1.2.0 的真实隔离 Runner。开场明确这一点，页面持续显示同样声明。模拟审批知识不等于教师 gold，Mock 理解验证不等于真实理解能力。

## 准备与重复演示

运行 `pwsh -NoProfile -File ./scripts/start-delivery.ps1`，检查全部长期服务 healthy。打开 http://127.0.0.1:5209，密码读取本机忽略文件 `.delivery/demo.env` 的 `DEMO_PASSWORD`，不投屏该文件。学生 `demo-student-1`，教师 `demo-teacher`，其他学生为 2—6 号。课程固定《仓颉语言设计》，练习为合成演示 match 穷举。

错误和修复源码分别来自 `data/demo/match-error.cj`、`data/demo/match-fixed.cj`。错误版遗漏 B 分支；修复版覆盖 A/B 并输出 2。不得用静态截图或伪造 execution_result 替代实际编译。每轮完成后，下一次提交开始新诊断；尚未完成的修复保留原诊断并通过正式 attempts API 关联。

自动彩排 `frontend/e2e/delivery-real.spec.ts` 直接连接已部署 API、PostgreSQL 和 Runner，没有响应拦截。它仅通过合成学生本人的 API 清理上轮未删记忆，保留删除凭证和旧彩排文件。单独运行前设置新的 `DELIVERY_BROWSER_EVIDENCE`，然后在 frontend 执行 `npx playwright test --config playwright.delivery.config.ts`；统一验证入口会自动配置它。所有 15 步都通过后才执行 `scripts/probe-delivery.ps1` 的只读事务核对。

## 操作、结果、恢复与时长

下列自动时长为 2026-10-12 已完成候选彩排的真实毫秒记录，适合核对链路，不代表人工讲解速度；人工建议总时长约 6—8 分钟，属于演示预算。最终提交彩排以外置 `rehearsal.json` 的逐步时间为准。

|步骤|实际操作与预期|失败恢复|候选自动时长 / 人工预算|
|---|---|---|---|
|1|学生 1 登录，看到课程与 Mock 声明|确认本机演示密码、课程种子、健康状态，重新登录|281 ms / 20 s|

|3|看到编译未通过及 non-exhaustive 诊断、工具链 1.2.0|检查 Runner 健康与失败证据，不把不可用解释为概念错误|149 ms / 30 s|
|4|显示结构化概念诊断和 match 穷举概念|检查合成批准知识和诊断状态；不可用时暂停该步|20 ms / 30 s|

## 数据库核对与展示边界

只读探针核对该轮原提交编译失败、重试成功、唯一关联、提示 1/2、两次 Mock 理解检查、接受/拒绝建议、两版记忆删除、来源私人文本清除、删除凭证与墓碑。浏览器另外核对相同查询反查和旧 token 401。任何一项失败均保留结果，不能用截图抵消。

截图在实际操作后生成，只作辅助材料。关闭 token-bearing 浏览器 trace/video，不保存密码或完整访问令牌。所有证据仅为软件与合成链路证据；真实教师标注、真实模型比较和学生试点尚未执行。
