# 知界·仓颉学伴：项目设计与 Agent 交接规格

> 状态：设计评审稿（2026-10-01）
> 目标赛事：西安交通大学《电信 T.A 杯》“AI+教育”创新应用技能大赛
> 建议赛道：赛道一——AI+高等教育 / AI+教学
> 首个试点课程：《仓颉语言设计》

## 1. 文档用途

本文档是项目的统一事实来源，供后续开发 Agent、测试 Agent 和材料 Agent 使用。任何 Agent 开始任务前必须先阅读本文档与仓库根目录的 `AGENTS.md`，不得自行扩大范围或改变关键产品决策。

本文描述产品边界、系统模块、数据流、安全约束、推荐技术基线、开发阶段、验收门槛和 Agent 协作方式。它不是逐文件编码任务清单；详细实现计划应在本设计通过用户评审后另行生成。

## 2. 已确认的关键决策

1. 产品名称暂定为“知界·仓颉学伴（KnowBound-CJ）”。
2. 产品价值主线是“仓颉语言概念误区诊断”，不是普通代码补全或答案生成。
3. 角色隔离记忆是核心技术壁垒，但服务于教学目标。
4. 首个试点课程为《仓颉语言设计》。首版按“仓颉语法与编程实践”组织内容，不包含编译器实现课程。
5. 首版只有教师和学生两类角色，不建设助教端。
6. 教师默认只能查看班级匿名统计、学生正式提交的作业以及学生主动授权分享的诊断摘要；不能读取学生私人对话或完整学习记忆。
7. 学生可以查看、纠正、拒绝写入和删除自己的长期学习记忆。
8. 首版只支持文本题、仓颉代码片段和编译运行反馈，不支持语音、视频或情绪识别。
9. 所有比赛成效数字必须来自真实实验；目标值不得表述为实际结果。

## 3. 产品目标与成功标准

### 3.1 产品目标

学生提交仓颉代码或概念题答案后，系统结合编译器反馈、课程概念图谱、典型误区库和该学生经授权保存的学习记忆，识别错误背后的概念根因，并通过逐级提示帮助学生自主修正。教师通过匿名化班级分析发现共性误区，调整教学内容。

### 3.2 成功标准

- 系统能够稳定完成“提交—编译—诊断—提示—重试—理解验证—记忆更新”的完整闭环。
- 教师标注测试集上的概念根因诊断准确率目标不低于 80%。
- 对 100 条越权与提示注入测试，跨学生和跨角色敏感数据泄露目标为 0。
- 删除记忆后，主数据库、向量索引和缓存均无法再次检索该内容。
- 至少完成一次 10—20 名学生参与的小规模试点；不足时必须如实说明限制。
- 教师端能够展示不暴露个体身份的班级误区热力图和变化趋势。

## 4. 非目标

首版不做以下内容：

- 通用编程教育平台或多语言在线 IDE；
- 全自动生成并替换学生完整代码；
- 训练自有基础大模型；
- 复杂多智能体协作框架；
- 学校统一身份认证、教务系统或成绩系统深度集成；
- 全量保存聊天记录；
- 自动给出正式课程成绩；
- 全校、多课程生产部署；
- 助教端、管理员端或家长端。

## 5. 用户与权限边界

### 5.1 学生

学生可以：

- 加入课程并完成教师发布的练习；
- 提交仓颉代码、概念题答案和自己的解释；
- 查看编译结果、误区诊断、证据和递进式提示；
- 多次修改并重新提交；
- 查看个人概念掌握图谱；
- 接受、修改或拒绝系统提出的记忆写入建议；
- 查看、纠正和删除自己的记忆；
- 主动向教师分享某次诊断摘要。

学生不能：

- 访问其他学生的提交、诊断或记忆；
- 查看教师资料、答案库和班级统计；
- 修改课程概念图谱或误区标签；
- 通过提示词改变系统角色或权限。

### 5.2 教师

教师可以：

- 创建和配置课程；
- 管理课程资料、题目、参考答案和典型误区；
- 编辑并发布概念图谱；
- 审核低置信度或学生申诉的诊断；
- 查看匿名化班级误区统计和教学效果；
- 查看正式提交的作业内容；
- 查看学生主动授权分享的诊断摘要；
- 配置课程级数据保留规则。

教师不能：

- 默认查看学生私人对话或完整个人记忆；
- 查询未达到匿名展示阈值的小样本分组；
- 将某名学生的记忆用于另一名学生的生成上下文；
- 绕过学生删除请求恢复已删除的个人学习记忆。

班级统计仅在样本数不少于 5 时展示；否则统一显示“样本不足”。

## 6. 课程知识范围

首版概念图谱覆盖以下主题：

1. 基础类型、变量、表达式和控制流；
2. 函数、参数、Lambda 和闭包；
3. `class`、`struct`、值类型与引用类型；
4. `interface`、继承、实现、直接扩展与接口扩展；
5. 泛型与 `where` 约束；
6. `enum` 与 `match` 模式匹配；
7. `Option<T>`、`Some`、`None` 与异常处理；
8. `spawn`、`Future<T>` 与并发任务；
9. 包、模块、`cjc`、`cjpm` 与项目构建。

首批典型误区至少包括：

- 混淆 `class` 的引用语义与 `struct` 的值语义；
- 误以为 `Array` 赋值后底层数据完全独立；
- `match` 分支未穷举且没有兜底；
- 把 `Option<T>` 当作其他语言中的普通空值；
- 混淆接口实现、直接扩展和接口扩展；
- 泛型约束位置或能力判断错误；
- 在 `spawn` 后立即 `get()`，无意中把并发写成串行；
- 认为枚举默认支持 `==`；
- 修改 `for-in` 中的不可变循环变量。

课程知识和示例必须由教师审核。涉及仓颉语义或 API 的实现任务，Agent 不得凭其他语言经验猜测，必须以当前 `cjc`/`cjpm` 工具链和仓颉知识库为准。

## 7. 核心学习闭环

1. 学生选择课程练习并提交答案或代码。
2. 权限服务确认用户、角色、课程和任务边界。
3. 代码任务进入隔离的仓颉执行器，采集编译错误、警告、退出状态和受限运行输出。
4. 诊断编排器将代码、编译反馈、题目要求和允许访问的课程知识传给诊断引擎。
5. 概念图谱服务定位相关概念、先修关系和典型误区。
6. 记忆服务在授权范围内提供该学生在当前课程的学习状态；不提供其他课程或其他用户数据。
7. 诊断引擎输出结构化结果：错误位置、错误类别、概念根因、证据、置信度和建议提示等级。
8. 低置信度结果要求学生回答额外诊断问题，或进入教师复核队列。
9. 提示服务按四级阶梯逐步提供帮助，不默认泄露完整答案。
10. 学生修改后重新提交，系统判断是否自主修复。
11. 学生用自己的话解释错误原因，系统进行理解验证。
12. 系统提出记忆写入建议，经学生确认后才进入长期记忆。
13. 分析服务只向教师输出达到匿名阈值的聚合结果。

## 8. 功能模块与边界

### 8.1 Web 前端

包含学生工作台和教师驾驶舱，共用认证、课程选择和错误展示组件。

学生端页面：课程首页、练习页、代码提交与反馈页、提示阶梯、个人概念图谱、记忆中心、授权记录。

教师端页面：课程配置、资料与题目管理、概念图谱编辑、典型误区管理、复核队列、班级误区热力图、实验统计。

前端只负责交互和展示，不自行判定权限，不直接连接数据库或模型服务。

### 8.2 API 与应用服务

负责认证、课程、练习、提交、诊断任务、提示、记忆、授权、教师分析和审计 API。所有敏感读取都必须经过统一权限中间件。

### 8.3 仓颉代码执行器

独立进程或独立容器运行 `cjc`/`cjpm`。输入为源码、允许的构建方式和资源限制；输出为结构化编译/运行结果。

最低安全要求：无外网、非 root、只读基础镜像、每次任务使用临时工作目录、5 秒默认超时、内存与进程数限制、输出长度上限、任务结束后删除工作目录。不得直接在 API 服务宿主环境运行不可信学生代码。

### 8.4 诊断编排器

组合题目、提交内容、编译结果、概念图谱、误区规则和允许访问的个人学习状态；调用模型并验证其结构化输出。它不直接拥有用户权限，所有数据必须由权限与记忆服务过滤后提供。

### 8.5 课程知识与概念图谱

首版使用关系数据库存储节点和边，不引入独立图数据库。主要对象为概念节点、先修关系、易混淆关系、题目关联、典型误区和教师审核状态。

### 8.6 记忆与授权服务

管理记忆建议、学生确认、版本、纠正、过期、删除、分享授权和撤销。记忆必须带有 `course_id`、`owner_user_id`、`memory_type`、`visibility`、`source`、`confidence`、`expires_at` 和状态字段。

### 8.7 权限与审计服务

统一执行用户、角色、课程、资源所有者和授权范围检查。每次敏感读取、授权、导出和删除都写入不可由普通用户修改的审计记录。

### 8.8 教师分析服务

只读取去标识化事件和统计结果。任何小于匿名阈值的分组不返回明细。教师分析服务不得反向连接私人对话表或完整记忆表。

### 8.9 模型网关

提供统一的模型调用接口、超时、重试、结构校验、日志脱敏和测试替身。业务模块不得直接绑定单一模型供应商。测试环境必须可以使用确定性的 mock provider。

## 10. 核心数据对象

- `User`：身份、角色和状态；
- `Course`：课程配置和数据保留策略；
- `Enrollment`：用户与课程关系；
- `Exercise`：题目、题型、关联概念和发布状态；
- `Submission`：学生输入、版本、时间和正式提交标记；
- `ExecutionResult`：编译命令摘要、诊断、退出码、资源使用和受限输出；
- `ConceptNode` / `ConceptEdge`：课程概念及关系；
- `MisconceptionPattern`：典型错误、根因、证据和教师审核状态；
- `Diagnosis`：错误类别、概念根因、证据、置信度和复核状态；
- `HintEvent`：提示等级、内容摘要和学生响应；
- `MemoryProposal`：待学生确认的记忆写入建议；
- `LearningMemory`：经确认的课程内个人学习状态；
- `ShareGrant`：学生对教师的诊断摘要授权；
- `AuditEvent`：敏感操作审计；
- `AggregateMetric`：匿名化班级指标。

原始学生代码与私人交互不得写入模型调用日志。用于实验的数据必须去标识化，并记录数据版本。

## 11. 最小 API 边界

接口名称可以调整，但职责不得混合。

- `POST /auth/login`
- `GET /courses`
- `GET /courses/{course_id}/exercises`
- `POST /exercises/{exercise_id}/submissions`
- `GET /submissions/{submission_id}`
- `GET /submissions/{submission_id}/diagnosis`
- `POST /diagnoses/{diagnosis_id}/hints/next`
- `POST /diagnoses/{diagnosis_id}/explanation-check`
- `GET /me/concept-mastery`
- `GET /me/memories`
- `POST /memory-proposals/{proposal_id}/accept`
- `POST /memory-proposals/{proposal_id}/reject`
- `PATCH /memories/{memory_id}`
- `DELETE /memories/{memory_id}`
- `POST /diagnoses/{diagnosis_id}/share-grants`
- `DELETE /share-grants/{grant_id}`
- `GET /teacher/courses/{course_id}/analytics`
- `GET /teacher/courses/{course_id}/review-queue`
- `POST /teacher/diagnoses/{diagnosis_id}/review`
- `POST /teacher/courses/{course_id}/concepts`
- `POST /teacher/courses/{course_id}/misconceptions`

所有资源 ID 都必须在服务端重新校验课程归属和用户权限，不能仅依赖前端隐藏入口。

## 12. 诊断输出契约

诊断引擎必须返回可验证的结构化对象，而不是自由文本：

```json
{
  "category": "conceptual|strategic|procedural|expression",
  "locations": [{"start_line": 1, "end_line": 3}],
  "concept_ids": ["cj.pattern-match.exhaustiveness"],
  "root_cause": "string",
  "evidence": ["compiler diagnostic or approved course evidence"],
  "confidence": 0.0,
  "recommended_hint_level": 1,
  "requires_teacher_review": false
}
```

任何字段缺失、概念 ID 不存在、置信度越界或证据为空都视为无效输出。低于课程设定阈值的结果不得写入长期记忆。

## 13. 提示与答案保护

四级提示定义如下：

1. 反思问题：提醒观察现象，不指出具体修改；
2. 概念提示：指出相关概念或先修知识；
3. 步骤提示：给出局部推导、伪代码或最小片段；
4. 完整解析：仅在多次尝试后或教师允许的任务中提供。

每次升级提示等级必须记录原因。模型输出在返回学生前需要执行答案泄露检查；若过早给出完整代码，则降低信息量并重新生成。

## 14. 记忆隔离与删除语义

### 14.1 写入

模型不能直接写长期记忆。它只能创建 `MemoryProposal`，向学生展示内容、来源、置信度和有效期。学生接受后才能创建 `LearningMemory`。

### 14.2 检索

记忆检索必须同时满足：当前用户是所有者、当前课程一致、记忆状态有效、未过期、用途与当前任务相符。向量检索前先做元数据过滤，检索后再次执行授权检查。

### 14.3 分享

学生只分享诊断摘要，不分享完整私人对话或全部记忆。授权必须有范围和可撤销状态。

### 14.4 删除

删除操作需要清理主记录、向量索引、派生缓存和未完成的模型任务引用。完成后使用相同用户与查询条件执行反向检索验证，并生成不包含原文的验证记录。统计数据已经完成不可逆匿名聚合时，可以保留聚合值，但不能重新识别个人。

## 15. 错误处理原则

- 编译器不可用：明确返回“执行服务暂不可用”，不让模型伪造编译结果；
- 模型超时：允许有限次数重试，仍失败则保留提交并提示稍后重试；
- 诊断置信度低：追加诊断问题或进入教师复核，不强行定性；
- 知识库无证据：不生成确定结论；
- 记忆冲突：保留版本与来源，让学生选择纠正或合并；
- 越权访问：统一返回不泄露资源是否存在的错误，并写审计日志；
- 删除部分失败：标记为待清理，禁止继续检索，并由后台重试直至全部完成；
- 小样本分析：不返回明细或可推断身份的组合维度。

## 16. 测试与验收

### 16.1 单元测试

- 权限策略、课程隔离和资源所有权；
- 诊断结构校验和置信度分支；
- 提示等级状态机；
- 记忆建议、接受、纠正、过期和删除；
- 匿名统计阈值；
- 仓颉执行结果解析。

### 16.2 集成测试

- 提交代码到获得诊断的完整路径；
- 模型 mock 下的确定性诊断；
- 数据库与向量索引的一致删除；
- 教师只能读取允许的数据；
- 执行器超时、资源超限和恶意输入处理。

### 16.3 端到端测试

- 学生完成一次完整纠错并接受记忆建议；
- 学生拒绝或删除记忆；
- 教师查看匿名误区热力图；
- 学生 A 无法读取学生 B 的任何资源；
- 教师无法读取未授权私人对话；
- 不同课程的记忆不发生串用。

### 16.4 教学评测

建立不少于 50 个、目标 100 个由教师标注的仓颉错误案例。至少比较：普通大模型、仅解释编译错误的系统、完整知界学伴。评测诊断准确率、自主修复率、同类错误复发率、迁移正确率和答案泄露率。

### 16.5 安全评测

建立不少于 100 条攻击测试，包括跨学生读取、冒充教师、跨课程记忆调用、提示注入、ID 枚举和删除后重新检索。

## 17. 分阶段开发流程

### 阶段 0：工程基线与风险验证

- 确认 `cjc -v`、`cjpm -v` 和 Docker 可用性；
- 固化仓颉工具链版本；
- 建立前后端、数据库和执行器骨架；
- 建立 CI、格式化、静态检查和测试命令；
- 写入首批架构决策记录（ADR）；
- 产出可运行的健康检查。

退出条件：一条命令可启动系统；CI 能运行空测试；执行器能够编译一个最小仓颉程序。

### 阶段 1：无 AI 的最小垂直切片

- 实现教师创建课程和练习；
- 实现学生提交仓颉代码；
- 接入隔离执行器；
- 展示真实编译结果；
- 建立用户、课程、练习、提交和执行结果数据模型。

退出条件：教师发布题目，学生提交后看到真实编译反馈；越权访问测试通过。

### 阶段 2：课程知识与确定性误区规则

- 建立概念节点、边和典型误区表；
- 导入首批教师审核的课程种子数据；
- 先使用确定性规则将部分编译错误映射到概念；
- 建立教师编辑和审核流程。

退出条件：至少 20 个典型错误能够稳定映射到审核过的概念根因。

### 阶段 3：AI 诊断与提示阶梯

- 接入模型网关和 mock provider；
- 实现结构化诊断契约；
- 实现证据约束、置信度和复核队列；
- 实现四级提示与答案泄露检查；
- 实现理解验证。

退出条件：完整诊断闭环通过端到端测试；无证据或低置信度时不会伪造结论。

### 阶段 4：角色隔离记忆

- 实现记忆建议、学生确认和课程内检索；
- 实现记忆查看、纠正、过期和删除；
- 实现诊断摘要授权与撤销；
- 实现双重权限过滤和审计；
- 建立攻击测试集。

退出条件：跨学生、跨角色和跨课程测试全部通过；删除后无法检索。

### 阶段 5：教师分析与产品完善

- 实现匿名化指标和样本阈值；
- 实现误区热力图和趋势；
- 完善学生个人概念图谱；
- 完成可访问性、空状态、错误状态和演示数据。

退出条件：教师能够据此识别至少一个班级共性误区，且不能反推出学生私人数据。

### 阶段 6：试点与评测

- 冻结评测数据版本；
- 完成专家标注一致性检查；
- 运行三组对照实验；
- 运行安全攻击测试；
- 汇总原始数据、统计方法和限制；
- 根据结果修复高优先级问题，不修改实验定义来迎合结果。

退出条件：结果可复算，所有图表能追溯到原始去标识化记录。

### 阶段 7：比赛交付

- 完成作品介绍文档和 300 字简介；
- 录制不超过 10 分钟的视频；
- 准备架构图、操作手册、测试报告和试点记录；
- 检查文件命名、大小、个人信息和版权；
- 在提交前完成一次全流程彩排。

## 18. Agent 工作包与依赖

工作包可以由不同 Agent 执行，但不是完全并行；共享契约必须先稳定。

1. **工程基线 Agent**：目录、容器、数据库、认证、CI 和 OpenAPI 基线。最先完成。
2. **仓颉执行器 Agent**：沙箱、工具链探测、编译运行协议和恶意代码测试。依赖阶段 0 的协议定义。
3. **课程知识 Agent**：概念图谱结构、种子数据、典型误区与教师审核流。可与执行器并行，但不得修改执行器协议。
4. **诊断 Agent**：诊断编排、模型网关、结构化输出、置信度和提示阶梯。依赖执行结果与知识接口。
5. **记忆安全 Agent**：记忆生命周期、授权、隔离、删除与安全测试。依赖认证和课程数据模型。
6. **前端 Agent**：学生工作台和教师驾驶舱。只依据 OpenAPI 契约开发，禁止直接耦合数据库结构。
7. **评测材料 Agent**：评测数据、试点流程、指标、图表和比赛材料。依赖稳定功能和真实测试结果。

共享高冲突文件包括数据库迁移、OpenAPI 契约、Docker Compose、环境变量示例和根级配置。任何 Agent 修改这些文件前必须先确认当前状态，并在交接记录中说明影响。

## 19. Agent 交接协议

每个开发任务必须按以下顺序执行：

1. 阅读 `AGENTS.md`、本文档、相关 ADR、接口契约和现有测试；
2. 明确任务范围、依赖和不修改区域；
3. 先补充或编写失败测试，再实现最小改动；
4. 不擅自增加依赖、角色、课程或基础设施；
5. 涉及仓颉语义时查询仓颉技能知识库，并用当前工具链验证；
6. 运行本模块测试和受影响的集成测试；
7. 更新接口文档、迁移说明和必要的 ADR；
8. 交接时报告修改文件、验证命令、结果、已知限制和后续依赖。

禁止把未验证的模型输出、虚构的试点数据或目标值写成真实结果。

## 20. 架构决策规则

以下变更必须新增 ADR 并获得用户确认：

- 改变主赛道或首个试点课程；
- 增加新的用户角色；
- 改变教师访问学生私人信息的边界；
- 更换前后端主框架或数据库；
- 将不可信代码移出隔离执行器；
- 允许模型直接写长期记忆；
- 引入新的外部数据源或第三方模型供应商；
- 修改实验分组或核心成效指标。

## 21. 比赛演示主线

演示只讲一条完整故事：学生提交含有典型仓颉误区的代码，系统结合真实编译反馈诊断概念根因，以逐级提示帮助其修复并验证理解；学生确认一条学习记忆；另一学生和教师尝试越权读取私人记忆均被拒绝；教师最终看到匿名化班级误区热力图和真实试点结果。

演示中的安全失败、诊断结果和统计数据必须来自可重复操作，不使用纯视频特效伪造。

## 22. 设计评审检查结果

- 未发现占位标记或未定义核心模块；
- 产品主线、角色边界、数据流和安全规则一致；
- 范围可拆为一个实现计划，不需要分成两个独立项目；
- 默认教师权限已明确，不存在“教师是否可读私人记忆”的双重解释；
- 技术栈是推荐基线，允许通过 ADR 提出替代方案；
- 成效目标与真实结果明确区分。
